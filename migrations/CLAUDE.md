# migrations/

Alembic, async template. `env.py` reads
`app.config.get_settings().database_url` and imports
`app.infrastructure.repositories` so `Base.metadata` sees every registered
model — don't hand-edit the DB URL here.

## Workflow

1. Add/change a model in `app/infrastructure/repositories/<concept>.py` (a
   new module must also be imported by `repositories/__init__.py`).
2. `uv run alembic revision --autogenerate -m "<message>"`.
3. **Read the generated file.** Autogenerate is a starting point, not
   truth — check `upgrade()`/`downgrade()` match your intent, delete any
   spurious/unrelated ops, and confirm portable types (`Uuid`,
   `DateTime(timezone=True)`, not SQLite-specific ones).
4. A custom column type can render as an unimported dotted path (e.g.
   `app.infrastructure.database.types.UTCDateTime()`, defined in
   `app/infrastructure/database/types.py`) — a `NameError` on upgrade, not
   just a lint nit. Replace it with the type's DDL-level `impl`
   (`sa.DateTime(timezone=True)`): a `TypeDecorator` only changes
   Python-side value processing, not the DDL, so the swap is safe.
5. `uv run ruff check migrations/ && uv run ruff format migrations/` — mypy
   excludes this directory but ruff doesn't, and autogenerated code usually
   trips `UP007`/`UP035`/import sorting.
6. Apply it to a throwaway DB and inspect the schema before committing
   (`make migrate` applies to the real one).
   `tests/infrastructure/test_migrations.py` then gates (a) no drift between
   models and migrations and (b) a full `upgrade head → downgrade base →
   upgrade head` round trip that must end at head with no drift — so a
   `downgrade()` that fails, or leaves residue, fails the suite.
